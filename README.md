# dev-workflow

One build workflow for AI coding agents, written for Claude Code and assembled from other people's skills plus one of mine. Matt Pocock's skills decide what happens next. My `changeable-software` skill decides what good looks like at each step. A workflow file ties them together and adds parallel ticket waves, so independent tickets build at the same time. I built it with [Claude](https://www.anthropic.com/claude), by [Anthropic](https://github.com/anthropics), as my pair, which seemed only fair for a workflow about building with an AI agent.

The full walkthrough is in [docs/workflow-guide.md](docs/workflow-guide.md). This page covers what's in the box, who made it, and how to install it.

## What's in the repo

| Path | What it is |
| --- | --- |
| `workflow/dev-workflow.md` | The workflow itself. Claude Code loads it into every session through an `@` import in `~/.claude/CLAUDE.md`. |
| `skills/changeable-software/` | The standards layer: design laws, testing standard, review checklist, review mode. Original to this repo. |
| `cloud/dev-workflow/SKILL.md` | The same workflow wrapped as a skill, for Claude Code on the web, where `~/.claude/CLAUDE.md` isn't loaded. Generated by `scripts/build_cloud_skill.sh`; don't edit it by hand. |
| `template.sha` | The first 12 hex characters of the sha256 of `workflow/dev-workflow.md`. `scripts/build_cloud_skill.sh` writes it, and a cloud session compares it with the skill's `Template sha256` line to spot a stale skill. |
| `scripts/` | `context_guard.py` (hooks that warn as the context window grows), `context_report.py` (weekly report of where tokens went) and `relay.sh` (opens a fresh session with a handoff prompt typed in, for the model switch before a build and the 400k relaunch). |
| `install.sh` | Installs everything below at user level, so every project gets it. |
| `docs/workflow-guide.md` | The long-form explanation. |

## Install

You need [Claude Code](https://docs.claude.com/en/docs/claude-code/overview), git and Node.js.

```bash
git clone https://github.com/weezyf1995-boop/dev-workflow.git
cd dev-workflow
bash install.sh
```

Then, once in every repo you build in, open Claude Code and run `/setup-matt-pocock-skills`. It records your issue tracker and label names, which `/to-tickets` and `/triage` need.

Check it worked by running `/memory` in a session: `dev-workflow.md` should be in the list.

**Don't also install the Pocock or Addy Osmani plugins.** The installer copies skills in by name. Adding either plugin on top gives you every skill twice, and Addy's full plugin brings back nineteen skills that compete with the Pocock flow.

**Claude Code on the web.** Cloud sessions don't read your local `~/.claude`. Add `skills/changeable-software` and `cloud/dev-workflow` to your account as skills, and install the Pocock and Addy Osmani skills there the same way.

## Other AI coding agents

The skills travel; the glue is written for Claude Code. Pocock's and Osmani's skills are plain Markdown that Codex, Cursor and other agents can use (`npx skills add` installs them for any supported agent through `-a <agent>`), and changeable-software is the same. The workflow file leans on Claude Code features: the `@` import in `CLAUDE.md`, subagents in git worktrees for parallel tickets, `/memory`, and the Opus and Sonnet model rule. On another agent, load `workflow/dev-workflow.md` the way that agent loads instructions (`AGENTS.md`, for example) and expect to adapt those parts. `install.sh` targets Claude Code only.

## Hooks

The installer copies the context guard but doesn't touch your settings. To turn it on, add these to `hooks` in `~/.claude/settings.json`:

```json
"SessionStart":     [{ "matcher": "resume|fork", "hooks": [{ "type": "command", "command": "python3 \"$HOME/.claude/scripts/context_guard.py\"", "timeout": 5 }] }],
"UserPromptSubmit": [{ "hooks": [{ "type": "command", "command": "python3 \"$HOME/.claude/scripts/context_guard.py\"", "timeout": 5 }] }],
"PostToolUse":      [{ "matcher": "Bash", "hooks": [{ "type": "command", "command": "python3 \"$HOME/.claude/scripts/context_guard.py\"", "timeout": 5 }] }]
```

`relay.sh` opens the session through the Claude desktop app's `claude://code/new` link on macOS, and new sessions take the model set by `"model"` in the same file. Set it to `"opus"` and the build session after a relay starts on Opus with no switch. Elsewhere, relay.sh prints the prompt to paste.

## Updating

Re-run `bash install.sh`. It pulls the latest third-party skills and moves any old copy of this repo's files to `~/.claude/skills-backup/` before replacing it.

## Contributing

Run `./check.sh` at the repo root before you push. It prints one line per check and exits non-zero if any check fails. CI runs the same script on Ubuntu and macOS, and you add a new check by adding a file to `checks/`.

Edit only `workflow/dev-workflow.md`, then run `scripts/build_cloud_skill.sh` and commit the cloud copy and `template.sha` with it. `./check.sh` fails if either differs from what the script would write. The maintainer's private sync job, which lives outside this repo, should call the same script.
